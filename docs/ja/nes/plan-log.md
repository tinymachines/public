# PLAN: Super Mario Bros. を一面ずつ、実機の上で

ベンチが遊び方を覚えていく様子を、図で残した記録だ。ボタンのバイトの一本の
スケジュールを模型の上で探し、電源投入からコンソールで遊ばせる。スケジュールは
伸びるたびに一面多くクリアする。ここにあるどの面も、次の面を計画する前に、命を
一つも失わずに実機の上でクリアした。図は実測だ (マリオの道筋は模型の RAM から、
ボタンは実機が遊んだスケジュールから)。表の判定はベンチ自身のログから来ている。
ゲームの絵は一枚も載せていない: 市販のカートリッジをグラバーで取ったフレームは
サイトに出さず、これらは数字から描いている。

`tools/plan-log.py` が、`docs/plan-log.json` (記録)、`exercise/smb-plan.txt`
(スケジュール)、そしてそのスケジュールを模型の上で再生したものから描いた。
ここで使う言葉は `docs/bench-language.md` のものだ。

![走行の全体: 面ごとの帯、それぞれの面でのマリオの進み、積み上がっていくスケジュールの項目数、そしてヘッドが流し込みを始めたところ](/nes/bench/plan-log-overview.svg)

## 手順

ベンチはゲームに反応できない。ヘッドを通した判断には、フレームを一枚取って
ブリッジへ一行送るので、およそ一秒半かかる。そのあいだに Super Mario Bros. は
ポーリング九十回ぶん進んでしまう。だからベンチは開ループで遊ぶ: スケジュール、
つまりコンソールがどのポーリングからどのバイトを読むかを言う `AT n hh` の行を
渡され、仕事はそのスケジュールを見つけることにある。どの面も同じ五つの段を、
この順に通った。そして最後の段が通るまで、次の面は始めなかった。

1. **模型の上で計画する。** `tools/plan.py` は `nes-console` の `branch` の
   例を動かす: 状態を丸ごと保存して読み込めるプロセスとしてのコンソールだ
   (`Console::save_state`。読み込みは、止まらずに走った走行とバイト単位で同じ
   だと証明してある)。実機が最後にクリアしたスケジュールの終わりから、一度に
   30 ポーリングの区間を探す。20 の動き (走る、歩く、止まる、戻る、A を押し
   続ける、5 ポーリングごとに始まる三つの高さの助走ジャンプ、そして水中では
   10 か 16 ポーリングごとに A を叩く) をそれぞれ区間の保存した状態から試し、
   その後に三通りの続き (走る、今すぐ跳ぶ、少し後で跳ぶ) をつなげる。動きは、
   その続きのどれかが生き残ったときだけ残す。残った動きは、面が終わったか、
   次にエリア、次にマリオがどこまで右へ行ったかで順位を付け、一番よいものを
   確定する。ある区間の動きがすべて死んだら、探索は一区間戻って次によいものを
   取り、一つのポーリングが四回失敗したら、その前の区間も諦める。
2. **通しで再生する。** スケジュール全体を電源投入から `watch` に通す
   (保存した状態も、計画するものも使わない): 始めたときと同じ残り人数で、次の
   面の始まりの画面まで行かなければならない。これが、計画するものが信じた
   スケジュールを二度捕まえた (勝った城を勝ちと認めていなかった。旗竿に届いたのが、
   スケジュールに入れ忘れた先読みの中だけだった)。
3. **数える。** UNO のスケジュールが輪になってから (2026-10-18) これはゲートでは
   なく覚え書きだ: ヘッドはコンソールがリセットを抜ける前に 480 項目を入れ、
   残りはポーリングが過ぎるにつれて流し込む。
4. **実機で遊ぶ。** ヘッドがベンチの Pi の上で台本を走らせる: 電源、温かい
   リセットの手順、すべての `AT` の行。グラバーは選んだポーリングでフレームを
   取る (サイトには出さない)。その後、走行の `bridge.log`、つまりコンソールが
   ポーリングごとに読んだバイトを、最後のリセットより後の台本と突き合わせる:
   抜けたポーリングも、違うポーリングも無いこと。コンソールが次の面の始まりの
   画面を見せたら、その面はクリアとして数える。
5. **プッシュする。** アドレスと取り込まれる文書の確認の後、道具と記録を
   コミットしてプッシュする。

探索が模型から読むもの。どれも信じる前に実測した: `$0770` はモード (1 は遊んで
いる、2 は城の斧の後)、`$000E` はマリオの状態 (08 は操作できる、0B は当たった、
06 は死んだ、04 は旗竿、05 は城へ歩くところ、02 と 03 は土管、07 はゲームが彼を
歩かせて入れるところ)、`$006D`:`$0086` はエリアの中の位置、`$00B5` は縦の画面
(1 を越えたら落下)、`$075A` は残り人数、`$0760` はエリア、`$075C` と `$075F` は
面とワールド。

下の図は、どれも一つの面だ: 横から見たマリオの道筋で、横は面の x、縦は彼の高さ。
彼が自分で動いているところは実線、ゲームが彼を留めているところ (土管、歩いて入る
ところ、旗竿) は破線で、A を押すたびに点がある (ジャンプ、または水中ではひと掻き)。
その下に、面のポーリングにわたるボタン: Right と Left と B は押している間の棒、
A は押すたびに一本の目盛り。

### 3-3

![ワールド 3-3: マリオの道筋とボタン](/nes/bench/plan-log-3-3.svg)

キノコの台の面で、深さ優先ではできなかった最初の面。x がおよそ 950 のところで、
マリオは低いキノコの上に立ち、ノコノコが向かって歩いてきて、その先には、そこから
のどの助走ジャンプでも上に届かない高い柱があった: どの動きも落ちるか、当たった。
先へ行く道は上で、真ん中の台に乗ってそこから渡るものだった。それは x を稼がない
ので一度も一位にならず、行き止まりが見えるより何区間も前に捨てられていた。小さな
変更を二つ試したが届かなかった (待ってから跳ぶ四つ目の続き、長くした行き詰まりの
窓)。届いたのはビームだ: `--beam 4` は区間ごとに、エリアと x と高さで区別される
一番よい位置を四つ残し、そのすべてを広げる。だから高い道筋が低い道筋の横で
生き残る。区間一つあたりおよそ四倍の手間がかかり、この面を三十分足らずで
計画した。上の道筋は、それまでの面が走ったところを登っている。

ベンチでの最初の走行は失敗したが、計画のせいではなかった: そのポーリングのログは
完璧だった (どのバイトも台本どおりで、抜けも無い) のに、絵はアトラクトモードの
ワールド 1-1 を、それからタイトルを映していた。コンソールが途中で勝手に再起動
したのだ。コンソールが自分から振る舞いを乱したのはこれで三度目で (その前に始まりの
失敗が二度)、疑わしいのはカートリッジのコネクタだ。接触が悪いと、ロックアウトの
チップがコンソールをリセットさせる。何も変えずに走らせた次の走行が、この面を
クリアした。

### 3-4

![ワールド 3-4: マリオの道筋とボタン](/nes/bench/plan-log-3-4.svg)

三つ目の城で、通しの再生が探索ではなく模型の欠陥のために拒んだ最初の計画。
計画するものは、各区間の前のポーリングの終わりでコンソールを止め、保存し、そこから
区間のボタンを渡す。だが模型の `RUN` は、そのポーリングが入っているフレームの
終わりで止まっていて、ポーリング 26030 のあたりで、一つのフレームがポーリングを
二つ含んでいた。二つ目はバイトが渡されるより先に過ぎてしまったので、模型はその
ジャンプを一ポーリング遅れで遊び、通しの再生と実機は時間どおりに遊んだ: 数ピクセル
の違いで、再生ではマリオはポーリング 26101 で、ファイアバーのあいだで当たった。
計画するものが、彼が通り抜けるのを見た場所だ。いま `RUN` はポーリングそのものの上で
止まり、もう過ぎたポーリングへの `AT` は、ブリッジが拒むのと同じように拒まれる。
同じ始まりからもう一度計画すると、この面は後戻りなしで通り、実機の上で一度目で
クリアした。

![ワールド 4-1: マリオの道筋とボタン](/nes/bench/plan-log-4-1.svg)

ジュゲムの面で、これまででいちばん長い: 後戻りなしの 51 区間、およそ二十分。
計画するものにとって新しいことは無い。ベンチでの最初の走行はどのポーリングも

### 4-2

![ワールド 4-2: マリオの道筋とボタン](/nes/bench/plan-log-4-2.svg)

これまででいちばん難しい面で、計画するものが自分だけでは終えられなかった最初の面。
五つの計画が失敗し、それぞれが何かを教えた:

1. 深さ優先は最初のパックンフラワーの土管の下で止まった: 先へ行く道はレンガの
   棚の上へ登ることで、x は少しも増えない。
2. ビームは天井の上へ出る道を見つけ、その上を走ってワープゾーンへ入った。そこの
   土管はワールド 4 を飛ばしてしまう。いまは一番上の列に立つことを死と数え
   (`--no-ceiling`)、ワープも死と数える。ワープとは、面が次の面以外のどこかへ
   変わることだ。(ワープの規則の最初の版はゲームのワープの旗 `$06D6` を読んでいて、
   それは間違いだった: 本当の道筋でも、最後の土管のそばで 1 になる。)
3. ビームは最後の高い土管で、その横に押しつけられたまま止まった: x だけで順位を
   つけたので、階段の上を捨てていた。その土管へのジャンプが始まるのは、そこだけだ。
   いまはビームの余地の一部が、マリオが立って届いたいちばん高い位置に回される
   (`--beam-high`)。
4. それでも止まり、模型の上で手で探してみてわけがわかった: 階段の上から、12
   ポーリング走って A を 30 押し続けると土管に乗るが、それはパックンフラワーが
   下がっている間だけで (およそ 36 から 138 ポーリングの待ち)、ジャンプは区間の
   終わりをまたぐ。先読みの中のどの進み方もその境目で A を離していたので、
   計画するものはそれを短いジャンプと判断した。いまは五つ目の進み方が A を押し
   続ける。
5. ビームはそれから土管の上に着き、またそれを失った。

そこで、その一区間だけは模型の上で手で探した: 階段の上にあるビーム自身の保存した
状態から、上の道筋 (待ち、走り、ジャンプ、それから出口の土管への二度目のジャンプ)
を、どの待ちでも、二つの走る長さで試し、生き残る一つをつないだ。計画するものは
そこから、出口の土管の外から旗竿まで三分足らずで進んだ (`--resume` はいま、保存した
ビームの状態と、そこへ届いたスケジュールから始める)。電源投入からの通しの再生は
スケジュール全体で「WORLD 4-3」まで行き、実機も一度目で同じだった。

### 4-3

![ワールド 4-3: マリオの道筋とボタン](/nes/bench/plan-log-4-3.svg)

キノコの台と、マリオが乗ると落ちるリフトの面。4-2 のビーム (四つの位置、そのうち
一つは高さのために残す) が自分だけで越えた: 41 区間、およそ 53 分、手で探したところは
無い。始まりの近くで、生きている位置が六つしかなく、そのいちばん良いものも後戻り
していたが、ビームはそこから進んだ。電源投入からの通しの再生はスケジュールを
「WORLD 4-4」まで運び、実機も一度目で同じだった。

### 4-4

![ワールド 4-4: マリオの道筋とボタン](/nes/bench/plan-log-4-4.svg)

最初の迷路。間違った道では、ゲームはマリオを輪の始まりへ戻し、それを二つの場所で
決める: 画面が頁 5 に届くとき、マリオは高いところ、y `$40` に立っていなければ
ならず、頁 9 に届くときは床の上、y `$B0` にいなければならない。この数はゲーム
自身のもので、そのコードが比べる三つの表に入っている。計画するものはいま、それを
その比較を通してゲームから読み出す。

1. 最初の計画は 500 ポーリングのあいだどこへも進まなかった。戻されるとき、
   マリオの x は一瞬、頁 `$FF` を読み、x で順位をつけると、それがこれまでで
   いちばん先だった。いまは、マリオ自身の操作のもとで一頁より大きく跳ぶことを、
   ワープと同じく死と数える。それより前の十五面の再生では、この規則は一度も
   働かない。
2. ビームはそれから下の通路を一つ目の関門まで走り、そこで止まった: 下の通路は
   上の通路と同じだけ右にある。高さの枠は、始まりの棚の上にあった。マリオが
   どこででも立つ、いちばん高い場所だ。
3. 迷路ではいま、高さの枠は、先読みが次の関門の望む高さでいちばん先まで立つ
   進み方に回される。区間の終わりで順位をつけると、上の帯へのジャンプはまだ
   宙にあって負けた。先読みで順位をつけると勝ち、ビームは一つ目の関門を自分だけで
   越えた。
4. 二つ目の関門で、ビームはいちばん上の棚で止まった。床の通路へは、ぶら下がった
   レンガの下にある、真ん中の床の一タイル幅のすき間からしか入れず、右へ走ると
   その上を越えてしまう。どの先読みも右へ走る。

そこで、その一区間は模型の上で手で探した。棚の上にあるビーム自身の保存した状態から:
真ん中の床へ降り、マリオがすき間の上で止まって落ちるまで 80 ポーリング左へ歩いて
戻り、それから走る。それをつなぐと、計画するものは床の通路から斧まで進んだ。
電源投入からの通しの再生はスケジュールを「WORLD 5-1」まで運び、実機も一度目で
同じだった。
