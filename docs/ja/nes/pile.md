# 手持ちの山にあるもの

新しい計画のために手元にある機材を、持ち主の写真から読み取ったもの。どの項目も、部品から**読み取った**もの（シルク、チップの刻印、抵抗のコード）と、その部品の系列の資料から来るものとを分けて書く。後者は測定ではない。ここにあるものは、そう書いていない限り、このベンチで電源を入れたことがない。

カートリッジの山（65C02 の一式、スタティック RAM、マスク ROM のアダプタ）は `cal-cart-build.md` にあり、ブリッジ自身の部品は `parts.md` にある。

### Stamp P4: パッドのファームウェアにそのまま起動する基板

![Stamp P4 のピン側](/nes/lab/pile-stamp-p4-pins.jpg)

![Stamp P4 の部品側](/nes/lab/pile-stamp-p4-parts.jpg)

- **読み取ったもの:** ESP32-P4NRW32（パッケージの中に 32 MB の PSRAM を持つ P4）、フラッシュは XMC 25QH128（128 Mbit、16 MB）、シルクに STAMP P4。作り手の名前は基板に印刷されていない。
- **シルクのまとまり:** CSI（カメラ、部品側の FPC コネクタ）、DSI（ディスプレイ）、RMII（イーサネット MAC のピン）、SDIO、LPG（低消費電力の GPIO）、5V、3V3、RST、そして左端に **G35/BOOT**。
- **USB:** Type-C が一つ、**G24/G25 (D-/D+)** に配線されている。ふつうは P4 の USB シリアル/JTAG であるフルスピードのポートだ。下端の HOST DM/DP のパッドはハイスピードのポート。
- **ボタンがない。** ROM のブートローダに入るには、RST を Low に引いて離す間（または電源が入る間）、G35/BOOT を GND につないでおく。
- **これはおそらく LITTLEGUY だ**（事務所のマシン、2026-10-05）: P4 で、ボタンがなく、`303a:0002 tinymachines NES Pad` として列挙される。`firmware/pad-usb` はまさにこのポート（PHY 0、GPIO24/25）を OTG コントローラに切り替える。この基板がシリアルポートを見せないのはそのためで、ただ一つのソケットがパッドになっている。ブートローダが答えるまでは未確認。
- **2026-10-06 に見えたもの**（ベンチのヘッドで）: 電源投入から一秒ほどのあいだ、P4 自身の USB シリアル/JTAG である `303a:1001` として列挙され、シリアルは **30:ED:A0:EA:99:6E**。その後 `pad-usb` がポートを取り、`303a:0002 tinymachines NES Pad`（フルスピード、100 mA、HID インターフェース一つ）として戻ってくる。これがチップの MAC だ。どの P4 の基板かは、まだブートローダ待ち。
- **系列の資料から。測っていない:** どの P4 にも Wi-Fi と BLE はない。高性能の RISC-V コアが二つと、低消費電力のコアが一つ。

### C6 DevKitC: 死んだ基板、脇に置いた

![DevKitC の表](/nes/lab/pile-c6-devkitc-front.jpg)

![DevKitC の裏](/nes/lab/pile-c6-devkitc-back.jpg)

- **読み取ったもの:** ESP32-C6-DevKitC-1 V1.2、モジュールは MCN8（8 MB のフラッシュ）と記された ESP32-C6-WROOM-1、裏に日付コード 2542 と 2526。Type-C のソケットが二つで、**USB**（C6 自身の USB シリアル/JTAG）と **UART**（ブリッジのチップ U3 を通る）と記されている。BOOT と RESET のボタン、**IO8 に RGB LED**、ジャンパ J5。
- **死んでいて、脇に置いた（持ち主、2026-10-05）。** パッドの図面が前提にしていた C6 の開発キットがこれで、2026-09-29 に死んでいるのが見つかった（どちらのソケットにも ROM のバナーが出ない）。裏の 10 と 8 と記されたヘッダのピンに残るフラックスとはんだは、その組み立てのものだ。これを使う予定は何もない。
- **系列の資料から:** Wi-Fi 6（2.4 GHz）、BLE 5、802.15.4（Thread、Zigbee）、RISC-V コアが一つ。

### C6 LCD: 画面とカードスロットを持つ C6

![C6 LCD の基板](/nes/lab/pile-c6-lcd-board.jpg)

- **読み取ったもの:** ESP32-C6-LCD-1.47、Waveshare のロゴ、40.000 MHz の水晶、Type-C が一つ、**BOOT** と **RST** のボタン、金属のケージの下にカードスロット、ヘッダのピンは 0 から 5、9、18、19、20、23、12、13、RXD、TXD、3V3、GND、5V。赤いラベルに C3 とある（誰かの札で、チップは C6 だ）。
- **画面**は反対の面にある。その写真はピントが合っておらず、残していない。大きさは製品名にある 1.47 インチ。
- **2026-10-05 に測った**（ベンチのヘッドでの `esp-reset --characterize`）: ESP32-C6FH8 (QFN32) rev v0.2、**パッケージの中に 8 MB のフラッシュ**、40 MHz の水晶、ベース MAC は b0:a6:04:8b:48:58、セキュアブートとフラッシュ暗号化はオフ、鍵のブロックはすべて空。C6 自身の USB シリアル/JTAG である `303a:1001` として列挙される。
- **動いていたもの:** `firmware/pad-ble`（「advertising as NES Pad」と印字した）。これは画面を一度も点けない。画面が暗いのはそのためで、故障ではない。
- **ベンダの wiki から**（waveshare.com/wiki/ESP32-C6-LCD-1.47、2026-10-05 に読んだ）: ST7789 のパネル、172 x 320。LCD は GPIO6 (MOSI)、7 (SCLK)、14 (CS)、15 (DC)、21 (RST)、22（バックライト）。カードスロットは 4 (CS) と 5 (MISO) で、6 と 7 を共有する。RGB LED は GPIO8。wiki はフラッシュを 4 MB と言い、チップは 8 と言う。
- **その仕事:** TRNG のエミッタで、取り込みは GPIO18（geiger `docs/HARDEN-PLAN.md`）。

### HW-399: 四チャンネル、遅い信号用

![HW-399 の部品側](/nes/lab/pile-hw399-front.jpg)

![HW-399 のピン側](/nes/lab/pile-hw399-back.jpg)

- **読み取ったもの:** Optoisolator HW-399、東芝の **TLP281-4 GB**（一つのパッケージにフォトトランジスタのフォトカプラが四つ、日付 1940）、221（220 Ω、入力ごとに一つ）と 512（5.1 k）のコードの抵抗、J3Y と記された SOT-23 のトランジスタが四つ。ピンは、入力側に IN1 から IN4、GND、NC。絶縁側に OUT1 から OUT4、HVCC、HGND。
- **測っていないもの:** 出力の極性（INn を駆動したとき OUTn が High になるか Low になるか）と、そのエッジの時間。このようなフォトトランジスタの部品はマイクロ秒単位で切り替わる。ボタン、リレー、遅いロジックのためのもので、時刻の記録のためのものではない。

### Iso_817_X1: 一チャンネル、ねじ端子

![Iso_817_X1 の部品側](/nes/lab/pile-iso817-front.jpg)

![Iso_817_X1 の裏](/nes/lab/pile-iso817-back.jpg)

- **読み取ったもの:** 裏に Iso_817_X1_V1.1 (303ISOX1011)、表に 2026.03.16、載っているのは東芝の **TLP785 GB** で、PC817 ではない（TLP785 は同じ四ピンのフォトトランジスタの仲間だ）。入力の端子は + と -、出力の端子は VCC、OUT、GND。表示灯は D1。
- **抵抗。基板自身の文字を正立させて読んだ:** 入力側に **R1 = 102、1 k**、出力側に **R2 = 103、10 k**。刻印は端子のラベルと直角に印刷されていて、逆向きに読むと 201 と E01 になる。テスターなら数秒で決着がつく。
- **同じ型**が NES のヘッドのリセット用フォトカプラだ（`wiring.md`、`Iso_817_X1`）。だからこの R1 は、あちらの入力抵抗についても、TRNG の図面の代役（geiger TM-TRNG-001 の三葉目は 1 k と仮定した）についても、いまのところ最良の読みになる。

### HP-16C: ポケットに入る 6502 の算術

![HP-16C のキーボード](/nes/lab/pile-hp16c-front.jpg)

![HP-16C の裏、リファレンスカード](/nes/lab/pile-hp16c-back.jpg)

- **読み取ったもの**（ベンチのカメラから）: 16C のバッジ、キーボード（HEX、DEC、OCT、BIN。SL、SR、RL、RR、RLC、RRC、ASR。MASKL、MASKR。AND、OR、XOR、NOT。WSIZE。SET COMPL の下に 1's、2's、UNSGN）、そして裏に成形されたリファレンスカード: エラーコード 0 から 6、どの演算がキャリー (C) と範囲外 (G) を立てるか、シフトとローテートの図、フラグ 0 から 5。
- **シリアル**は上の縁に成形されている: USA と、2447A と読める接頭部。HP の慣例では 1984 年の第 47 週、米国製になる。残りの桁は真上からのカメラには薄すぎる。
- **表示は空だった**（この一枚では）: 電源が切れているか、三つのボタン電池（LR44 か SR44）が切れている。このベンチではまだ電源を入れていない。
- **系列の資料から:** 整数のワード長は 1 から 64 ビット、符号付きは 1 の補数か 2 の補数、または符号なしで、キャリーと範囲外のフラグを持つ。中身は HP の Nut プロセッサ。
- **なぜここにあるか:** ワード長 8、2 の補数にすると、6502 が計算するものを計算する（ADC のキャリーとオーバーフロー、ASL、LSR、ROL、ROR）。そしてシミュレータと何も共有しない。公開されている命令表がタイミングについて果たすのと同じ種類の証人だ。
